# 统一处理任务状态

## 正常路径

人工、Agent、邮件提交材料后创建一个业务任务。后台 worker 可以分开执行，但运营队列展示同一个任务的当前阶段。

排队中 → 解析文件 → 整理资料 → 保存附件/创建岗位 → 已入库 → 匹配中 → 匹配完成或无匹配结果。

- 解析文件：提取文本、页面截图，保留原件。
- 整理资料：按候选人/JD 功能的模型生成结构化职业资料。
- 已入库：候选人或岗位已经持久保存，不代表匹配完成。
- 匹配中：对子任务中仍在处理的人岗组合评分。
- 匹配完成：所有当前匹配子任务完成，结果未过期且当前权限可读取。
- 无匹配结果：所有匹配子任务结束且均返回 NO_RESULTS。不是解析失败，也不能凭此断言候选人没有能力。
- 已入库·未匹配：自动匹配关闭时的终点，不显示成匹配完成。

## 异常与恢复

| 状态 | 含义 | 恢复位置 |
| --- | --- | --- |
| 待核对材料/身份 | 输入类型或身份不确定 | 保留原件，核对材料 |
| 失败 | 文件处理、模型提取或入库失败 | 从已保存 checkpoint 恢复材料任务 |
| 匹配失败 | 匹配入队失败、评分失败或部分组合失败 | 重试失败的匹配阶段，保留已入库资料 |
| 需要重新匹配 | 资料版本或候选池已变 | 重新生成当前版本结果 |

邮件列表的「已解析」是邮件材料阶段的终点，与统一队列的匹配终点不同。匹配完成不表示已联系、已推荐、已发送或已录用。手动匹配使用同一评分服务，在当前页面显示进度，不新增一条材料任务。
