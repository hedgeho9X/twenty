## 3. 继续验收的边界

公司新建、JD最终批量创建、门户资料保存和撤回均已补充真实页面闭环，先前HTTP/MCP与前端状态回归另行保留。新SIWC本人授权及授权后真实调用/续期仍未验证；页面能展示零连接状态不等于完成订阅接入。

曾一次两个页面一起回到欢迎页；目前只能确认认证失败会触发退出，日志无法定位首次失败请求，不能归因于独立脚本的JWT续签。用户授权代理登录后，使用原私有本地副本凭据通过正常表单恢复，未修改密码、认证规则或其他浏览器空间。新会话稳定性继续观察。

门户最初出现空响应JSON解析错误，实查同源/recruiting-portal空404，而同一能力直连API为201 JSON；订阅根路径同源则错误返回SPA HTML。已补本地严格路径代理，并对空错误体/成功但无JSON给出可读提示，保留服务端权限错误。70项定向回归、前端全包TS、相关lint通过；正常页面已重新观察到合成候选人资料及附件。未改变能力授权或原生会话规则。

批量JD确认曾遇自动化鼠标派发超时；两条预分配ID均经独立API回查404，页面仍为DRAFT且按钮enabled，因此没有盲目第二次点击。随后以正常焦点和Enter确认一次，页面返回两条已创建；根会话独立读回真实RECRUITING版本并逐ID关闭。预览生成使用727输入/579输出tokens，后台自动匹配用量没有做本轮完整计量，不称零模型。新岗位清理证据qa-final-ui-jd-actual-cleanup-evidence.json，原52混合池和旧六fixture证据未覆盖。
