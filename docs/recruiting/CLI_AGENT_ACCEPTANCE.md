# 招聘 Agent CLI 验收

2026-11-02，目标为本地 B 实例。CLI 0.2.0，所有业务请求均使用新建的一小时有效原生 API Key；未借用用户会话执行 CLI 业务动作。验收 Key 绑定当前 Admin 角色，因此证明的是有招聘读写权限的 Key，不代表受限 Key 自动拥有所有权限。

## 命令与 Agent 接口

只发现七组业务命令：companies、jobs、candidates、tasks、match、draft、share；另有 auth status 和按组 schema/help。不暴露底层对象 CRUD、工具注册、工作流节点或通用 MCP 目录。旧命令仍兼容，但不进入默认帮助。

Skill 位于 `.agents/skills/fanhan-recruiting`，包含 Codex 默认入口元数据与可供通用 Agent 使用的角色说明。Agent 需要终端执行能力与环境注入的 Key/Base URL；没有另建模型服务或自运行后台 Agent。

## 已执行的场景

1. 验证 Key；创建一家公司。
2. 导入一份纯文字 JD，等待解析、创建与关联匹配。
3. 上传一份合成简历，等待解析、候选人入库与关联匹配；读取候选人资料。
4. 定向人找岗、岗找人，各一对，等待终态。
5. 选前五（本案例可用结果一条）生成文案，编辑并保存。
6. 创建岗位+候选人分享，列举；设置岗位停招，公开页回读 CLOSED。
7. 撤销分享，匿名再读取返回403；同时撤销文案的自动分享。

共14次CLI业务操作成功。最终通过原生API清理10条本轮创建的业务记录，均200；临时Key已撤销。公司/在招岗位/候选人数量回到40/45/3。私有逐步记录在 `.local/recruiting/fanhan-agent-evidence.json`，不包含API Key。

## 修正与测试

- `--wait` 不在 STORED/PENDING 时抢先结束，继续等待关联匹配。超时保留任务kind/id。
- 空JSON响应不冒充成功；失败/部分失败退出码区分。
- 分组帮助只输出需要的动作；默认文案选前五，也支持指定ID。
- 16项CLI/上传回归通过，Skill校验通过，npm打包文件检查通过。

这次验证了CLI的接口与流程，并未声称无人监督Agent对所有自然语言任务都能正确规划。推荐质量、失败JD编辑、过期任务批量重算与筛选仍见当前待办。
