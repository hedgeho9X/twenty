# 合同模块兼容与保留边界

## 1. 现状盘点

迁入副本含11份company.contractDetails，均为legalName、creditCode、address、contactName、phone五字段；10家公司为SIGNED、2家为PENDING。原始公司没有外部contractDraftId或contractPreparation内容，也没有已生成的签约提醒任务。以上为本地盘点，不声称外部平台存在或不存在实际合同。

旧实现是固定RPO模板资料→内部TODO→法大大autoStart:false草稿→负责人打开短时编辑链接手工发起，最终状态手工确认；不自动签署或通知客户。原配置要求真实平台应用、己方企业/成员与签署模板，旧说明明确没有配置、不要做沙箱签约。

## 2. 本地保留能力

公司与岗位页提供合同资料和内部提醒。五字段、原有状态及外部草稿标记保留；资料与实际状态只允许当前公司负责人直接本人操作，Key、应用、Agent委托和冒用会话不能确认已发起/已签署。已发起/签署或外部创建锁存在时不覆盖模板资料。

内部提醒按公司稳定ID复用，关联原生task/taskTarget并分配公司负责人，未指定负责人则保持未分配。重试不覆盖人工编辑的任务。确认状态后尝试完成已有提醒，任务同步失败不回滚已保存的公司状态。MCP/CLI可读状态或创建内部提醒，不能声明实际签署。

旧“合同 · 准备签约”外部入口已停用，避免点击后进入缺配置的旧执行链；原菜单状态纳入本地导航备份可恢复。当前没有签约平台连接、外部草稿创建或编辑链接，不把内部任务当外部合同，也不重启旧生产工作流。

## 3. 并发与验证

实际测试发现PostgreSQL时间戳含微秒，而普通JS Date只保留毫秒，直接等值比较会误报冲突。使用官方ORM的getRawAndEntities同次读取资料与原始版本，将完整版本和当前负责人放在原生UPDATE条件中，继续保留字段/行权限、校验和事件；没有直接绕过权限写库。

真实本地合成验证：重复请求同一任务、1条公司关联、资料保存、旧版本409、同版本并发201/409、Key声明签署403、模拟确认后任务DONE。合成公司的签署/资料/负责人已恢复原值；其余原有公司合同字段摘要前后一致。没有外部请求。4项业务测试、前后端TS及相关lint通过；界面仍待浏览器验收。

接口为GET/POST /recruiting/contracts/:id、POST reminder。修改须带GET返回的version；不要将人类显示时间作为写入版本。原生MCP为contract_status/contract_reminder，CLI为contract status/reminder --company-id ID。
