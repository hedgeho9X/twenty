# 招聘匹配评测与本地复现

## 1. 样本与证据边界

第一轮固定8位候选人、46个真实在招岗位，共368对实际Jev评分；按候选人分4人调优组、4人保留组。先按固定种子哈希抽样并落盘，再读取材料、生成标签；排除了旧30人、69个输入排错样本、8个窗口排错样本和合成fixture。没有按结果换人。

冻结manifest的SHA256：1c6712cb449c46f309ef52498138f4daf57be736c0707758f61ed1389845cc32。原件通过本人原生文件授权下载，9份文件完成解析，18页截图，另有TXT文字资料。自动解析状态complete不是OCR或语义准确性的人工证明。

独立机器初审看到全部原件解析文字、岗位和公司上下文，以及每人Jev前五加2个哈希抽取对照岗，顺序打乱、不提供Jev分数或排名。判断提示及schema先冻结，原始输出不因后续核对修改。初审没有输入截图，因此仍需后续多模态和人工核对。该抽样只检查提出的前五质量，不能估计全库召回率。

Jev实际新评分368次，上报费用0.108646524美元，输入2,586,822 tokens，输出6,256 tokens。每位46岗运行约10.4～12.9秒；机器初审约29.1～35.0秒/位。订阅模型的内部API记账为零不代表没有订阅额度消耗，模型用量须另按原生Agent统计。

机器初审的前五可沟通率95%与排序一致率约95%只表示这两个模型在当前小样本上的一致性，不能写成“招聘准确率95%”。引用逐字核对率偏低，表明初审会改写或拼接证据；所有自由文本理由仍需人工核对，不能当Jev理由。

## 3. 已发现的分歧

保留组初审将一例“偏好远程、岗位线下”判为硬冲突，而程序列为待确认。核对原件只有“岗位类型：远程”，没有明确拒绝线下，因此保持待确认，不把偏好自动升级成硬排除。原始机器标签保留，另存Agent核对意见；这不是人工gold。

本轮没有程序排除样本，无法估计“未知被误拒”的概率，报告该指标为unknown，不写0%。这8位在结果查看后也不再属于未见样本；下一次调参后只能称其回归集，另固定新保留组才能报告新的未见样本表现。

## 4. 复现与迭代

在本地B使用项目Node运行ops/recruiting/prepare-rsi.mjs、run-rsi-matches.mjs、judge-rsi.mjs、report-rsi.mjs，先准备原始实验work目录。prepare需要--source指向该目录。manifest已存在则复用；任务使用固定幂等键和持久runId，原件、输入、模型结果和报告只写.local/recruiting/evaluations/rsi-v1，权限600，不提交带个人资料或签名URL的文件。

judge使用无业务工具/触发器的独立原生Agent，模型chatgpt-subscription/gpt-5.6-sol。需要显式临时启用本地ai-queue worker，启动前核对该队列，完成后停止；不得因此启动邮件、旧工作流或发送队列。官方Agent结构化输出目前只支持顶层primitive，评测按slot展开字段并逐项验证，不把它冒充任意嵌套JSONSchema。

下一轮先分析调优组，提出单一有界改动，再用冻结输入回归，记录变更、成本和覆盖。缺失资料、无标签、API失败、部分覆盖和模型不同意均单独表示；不得为提高指标删掉失败样本或回写伪造标签。
