# 候选人入口与分享边界

## 1. 原生能力与业务扩展

已核对官方RecordShare：它管理工作区成员/角色的内部记录权限，没有候选人匿名填写表单、简历接收及撤回后受控资料快照的完整业务入口。本功能增加同进程业务控制器，继续复用官方记录权限、文件生命周期、队列、缓存和当前Actor重建，不引入外部门户服务或万能管理员Token。

## 2. 能力链接

门户凭据为单独用途的两段签名数据，不是原生JWT。只包含邀请、有效期、nonce及稳定Actor引用；候选人与岗位范围保存在受服务端MAC保护的邀请记录。匿名请求在正文传凭据、浏览器不继承登录Cookie，链接片段不发送给服务端或Referrer。

每次访问重新检查邀请状态、到期、原创建者当前权限和候选人角色。复制能力链接仅允许原创建主体，其他有权限的运营人员可自行新建；API Key创建的链接有效期不超出其授权期限。所有写操作按候选人加单一锁，不嵌套申请锁会话。每入口有请求频率、文件数量与总量限制。

## 3. 资料与分享

候选人可填写本人求职资料、上传新版简历、选择岗位兴趣，分别确认或撤回分享。新的简历经统一上传/解析/结构化入库队列更新职业资料，历史原件和人工列保留。自报偏好单独标明来源，不把未知选项当明确拒绝。

企业预览只展示候选人确认的公开职业/联系信息和勾选简历。原始邮件、HTML邮件正文、运营服务笔记、旧复杂检索JSON及原生带凭据下载URL不会进入该投影。确认时冻结公开数据、所选文件与岗位/公司版本；变化后需重新确认。

分享授权是独立签名记录，不能靠修改person.candidatePortalState伪造。撤回立即阻止后续企业查看与下载；重新确认产生新授权时，旧企业链接不会复活。原入口撤销或到期也会阻止其授权链上的继续访问。已被接收方保存的副本无法通过本系统删除。
