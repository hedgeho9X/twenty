# 当前需求完成度核对

核对范围：本地 Twenty 重建；以本轮最新用户决定覆盖早期 DELIVERY_GOAL/NEXT_ACTIONS 中的旧设计。本文依据源码、现有文档及本轮只读接口检查，不创建测试业务记录、不调用模型、不修改线上。

## 1. 已落实的主要范围

- 官方仓库 fork 与独立本地环境；历史业务数据和文件曾完成迁移。之后按用户指示清空本地业务重新验收，原备份保留，不能将当前空岗位库称为迁移丢失。
- 公司选择/创建、多个纯文字 JD 提交；两步结束后进入任务，取消强制第三步预览确认和 JD 补充说明。
- 手动/API/邮件共用材料入口；正文、附件、内嵌资源归档；Docling 与页面预览；结构化候选人资料、可选说明、expectedRoles/category；解析结果 UI 和折叠 JSON。
- 同一业务任务串起材料处理、入库和匹配；独立失败/重试及状态说明。手动匹配留在当前页。
- 双向 Jev 评分、条件过滤和版本缓存；最多十个结果，初始显示/选中五个，加载剩余五个；选中结果生成可保存、编辑、复制的文案。
- 设置 → AI 独立账号 OAuth、加密存储/刷新、额度/目录、业务功能选模和 Jev 配置/连接测试。独立账号真实授权/刷新/结构化调用及重启验收完成；旧本机凭据读取与回退代码删除。
- 已取消合同业务入口、独立问候/发布页和本地 MinIO；不恢复这些作为未完成项。完整 AI 用量分析页按用户要求不做；当前额度显示不等同于用量分析平台。

- 公司 1；有效岗位 0；候选人 1；邮件归档 1；统一任务 2。
- 两条任务分别是 NO_RESULTS 和 FAILED。当前有 0 个有效岗位，因此不能用该运行快照验证十条匹配结果的完整交互。

- ChatGPT 独立连接已启用，API 正常。未发起新的业务解析、评分或对外通信。

## 3. 尚需补齐或核对

### 3.1 最终版本的完整业务验收

以前的解析/匹配实验和单元测试不能代替最近 UI、数据重置、十条选择和独立账号修改之后的端到端验收。需在隔离验收数据上完成：公司 → 多条有效 JD → 简历上传/邮件 → 解析资料 → 入库 → 两方向匹配 → 前十/默认五条 → 文案生成、编辑、重开与复制。同时覆盖失败重试和资料变更后重新匹配。当前未执行这轮新数据验收。

### 3.2 结果筛选的语义

MatchSelection 已有手动勾选、全选/取消、加载更多，但没有关键词、公司或分数条件筛选控件。用户说的“筛选”若包含这些条件，仍需实现；不能把手动取消勾选说成已完成条件筛选。

### 3.3 Agent 工具与最新 UI 的能力对齐

HTTP 和原生 MCP 的 draft_submit 可携带 matchRunId/selectedIds。项目 CLI 的 draft 命令仍是旧的单候选人/单岗位输入，没有选定匹配结果生成文案的参数；queue list 仍按 intake/match/draft/mail 分类查询，没有统一 processing-tasks 入口。若要求 Agent 用该 CLI 完成当前实习生整套操作，这两处仍需补齐并重新验收。

### 3.4 匹配的业务质量验收

已有固定 8×46 Jev 评分与机器初审、保留样本和离线报告，且记录了引用失真、标签不足和分组限制。但没有业务方确认的标准答案，不能将机器之间的一致率称为招聘准确率。最新解析输入和前十结果需抽样人工验收，明确误判、漏判和不适合结果。

### 3.5 需求与交付文档收口

DELIVERY_GOAL/NEXT_ACTIONS 中仍有旧的前五上限、第三步确认、合同/独立发布草稿、MinIO、待订阅授权等条目。应按最新决定整理，避免下一轮照旧清单恢复已删除功能。保留历史证据，不将旧勾选直接当当前完成度。

- 原需求文字第 45–49 行明确包含联系候选人、推荐给公司；会议逐字稿第 163 行讨论复制话术及已联系、等待反馈、面试、已结束等跟进状态。
- 旧项目的候选人门户已有资料填写、意向/分享同意、撤回和企业预览能力；本轮对话中用户认可过保留门户方向。
