# 本地业务数据清理

## 范围

仅针对源码环境 `localhost:23000`、专用 PostgreSQL `localhost:25432/recruiting`、Valkey `localhost:26379/0` 和 `.local/recruiting/storage`。用户已明确选择“清空全部业务数据，包括公司、岗位、候选人和处理记录，从空白开始验收”。旧环境 `localhost:13000`、外部邮箱和远端部署未修改。

保留登录与成员、模型 Provider、邮箱连接与游标、权限组、对象/字段/视图元数据、应用代码和头像。清空其余 59 张工作区业务表，移除业务文件引用和活动目录中的原件/解析页图，重置专用缓存与队列。本地合成测试邮箱的 5 封邮件先导出原文，再重建空邮箱；外部邮箱不在清理范围。

## 执行与保护

`ops/recruiting/reset-local-business.mjs` 默认只输出计划，显式 `--apply` 才清理；运行前必须停止本地 API、worker 和解析器。`local-reset-guard.mjs` 校验数据库地址、端口、库名、缓存及存储路径，拒绝远端、旧环境、连接参数覆盖和不匹配的目录。Docker 项目必须为 `twenty-recruiting`，活动任务数必须为 0。

先生成完整数据库 dump 并用 pg_restore 读取目录校验，保存缓存快照；原存储树和解析输出整体移到私有备份目录，仅将应用代码/头像复制回活动目录。数据库事务只清空枚举后的业务表，不使用跨 schema 的 CASCADE。提交前对登录、成员、模型及邮箱配置计算前后摘要，必须一致。事务失败会回滚，提交前出错时恢复文件树。

备份位于 `.local/recruiting/backups/business-reset-2026-11-01T10-59-36-250Z/`：

- `database.dump`：完整数据库快照。
- `storage/`、`parser-output/`：清理前完整文件与页图。
- `cache.rdb`：清理前专用缓存快照。
- `test-mailbox/`：本地测试邮箱原文。
- `before.json`、`report.json`：各表计数与受保护配置摘要。

恢复时先停止相关服务，在同一个隔离数据库恢复完整 dump，再恢复对应存储树和页图。恢复整份快照会回到清理前状态，不能与清理后新建的业务记录直接混合。代码和对象定义不需要回退。

## 验证

本次 59 张业务表计数全部为 0，删除 1,481 条业务文件引用，受保护配置摘要一致。服务恢复后公司、候选人、岗位、材料队列、匹配和邮件六个鉴权接口均为 200 且记录数为 0。页面显示“暂无匹配记录”，没有为验收重新创建样例。清理目标保护测试 9 项通过。

后续存储已切为本地 MinIO，原磁盘专用清理脚本会在 S3 模式拒绝执行。再次清理业务需要同时安排桶快照与对象清理，不能只删除磁盘目录。
