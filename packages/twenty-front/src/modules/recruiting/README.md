# 招聘工作台前端

页面入口在 `src/pages/recruiting/RecruitingWorkspacePage.tsx`，负责导航和 URL 状态。此目录按业务组织组件、类型和单元测试，页面不直接调用模型或写数据库。

| 目录 | 职责 |
| --- | --- |
| `companies/` | 公司选择、岗位文字批量录入、已有岗位与岗位编辑；组件和公司/JD 类型放在一起 |
| `intake/` | 候选人上传入口及材料任务、上传回执、候选人类型 |
| `mail/` | 邮件列表、正文、附件预览入口与邮箱设置 |
| `queue/` | 材料/匹配处理队列和任务详情 |
| `matching/` | 匹配列表、手动匹配、公司上下文与打分事实 |
| `drafts/` | 问候与发布草稿的展示和编辑 |
| `portal/` | 资料确认、分享入口和门户请求适配 |
| `activities/` | 人工跟进记录 |
| `navigation/` | Twenty 原生侧边栏的招聘入口 |
| `shared/` | 跨业务使用的文件预览、资料卡、记录选择器、主题样式、请求与查询工具 |
| `__tests__/` | 跨多个业务页面的交互测试；单域测试放在对应组件或请求工具旁 |

每个业务目录内部按需要设置 `components/`、`types/`，不要求空目录或统一模板。目录已表达业务归属，因此文件名使用 `CompanyJobIntake.tsx`、`MailList.tsx` 等名称；现有导出符号保留以稳定跨模块引用。

依赖方向：页面组装业务模块，业务模块引用 `shared`。`shared` 不导入具体业务页面；跨业务资料展示放到共享组件，通过参数传入。跨目录引用使用 `@/recruiting/...`，同目录引用可以使用相对路径。

与后端的数据链路保持一致：接收材料返回任务 → 队列查询处理阶段 → 读取入库资料与独立匹配结果。
